# LLM-wiki — верхний уровень (карта неймспейса)

Корень репозитория — **верхний** уровень (level) личного неймспейса: meta-vault
(`meta-vault/`) + домены, всё в одном репозитории. Это папка-контейнер, не один
проект. Терминология — `meta-vault/glossary.md`.

Финальная цель — **LLM-независимое хранилище**: данные = читаемый markdown,
переживающий любой инструмент. Движок/клиент выкидываемо-переписываем; данные
остаются. Кэш клиента (`~/.claude/` и т.п.) — сменный, **не** источник правды.

> **Инвариант (все уровни — повторяется дословно, наследования нет):** NEVER
> `AskUserQuestion` / popup-диалоги с вариантами — вопросы владельцу всегда
> обычным текстом. **Ход первый — разговор, не работа:** без записей и
> многошаговых прогонов до слова владельца; хедж («вроде», «может») — мысль
> вслух, не приказ. Полный набор правил владелец держит в
> `meta-vault/preferences.md` и правит под себя.

## Уровни неймспейса (иерархия)

Корень — верх: доступ ко всему, связи вниз через `meta-vault/`. Ниже — домены,
каждый в своём scope:

- **`project/`** — домен-заготовка под первое дело владельца. Безымянный
  намеренно: **переименуй под своё** (магазин, практика, курс — что ведёшь),
  настрой дверь по пометкам `<настрой>`. Новые домены рождай из
  `meta-vault/vault-template.md`.
- **`office/`** — бэк-офис: юрлицо, налоги, финансы, архив документов.
  Дом всех бумаг владельца.

**Иерархия, не демократия:** top-агент пишет во все уровни ниже; нижние
горизонтально друг другу не пишут. Работая в нижнем уровне, агент подчиняется
**локальному** `CLAUDE.md` этого уровня.

## Агент этого уровня

Агенты безымянны, пока владелец не решил иначе; роль определяется тем, чем
агент **владеет**, а не высотой. Агент верхнего уровня владеет неймспейсом:
канон, карта, решения, маршрутизация. Режимы:

- **Governance** — пишет вниз во все уровни; следит, чтобы карта совпадала
  с реальностью.
- **Навигатор (read-mode)** — не знаешь, куда идти: спускается по уровням,
  находит дверь, маршрутизирует. Без записи.
- **Диспатч** — вызывает работу в доменах, **всегда с планом, который владелец
  читает** до запуска.
- Продукт **не** производит: работа над содержимым домена ведётся в самом
  домене, по его правилам.

## Раскладка корня

- `CLAUDE.md` — эта дверь (карта неймспейса).
- `meta-vault/` — meta-vault: метод, решения, реестры, задачи, связи вниз ко
  всем доменам. Старт — `HOME.md`.
- `project/` — домен-заготовка: своя дверь + `project-vault/` + `docs/` +
  `inbox/` (файлы — вне git).
- `office/` — бэк-офис: своя дверь + `office-vault/` + `docs/` + `inbox/`
  (бумаги — вне git).
- `secrets/` — доступы (вне git, NEVER commit/sync/index; контракт в README).

## Границы

- Не переименовывать уровни втихую и не переписывать их git-историю; смена
  имени домена (включая `project/` → своё) — осознанный шаг с обновлением
  всех дверей и карт.
- Секреты только в `secrets/` / `.env`, никогда в трекаемых файлах — только
  указатели (`meta-vault/secrets-map.md`).
- Документы, файлы доменов и секреты в git не попадают по построению
  (`.gitignore`). **Свою копию держи приватной**: это публичный шаблон, но
  твой неймспейс с реальными данными — приватный или локальный репозиторий.
- Тяжёлые файлы (сканы, PDF, медиа) живут в `docs/`-папках вне git;
  в vault — карточки-указатели.

## Закрытие сессии — конвент уровня

Дерево менялось за сессию → перед закрытием агент закрывает записи уровня:
статус домена / карта / [[meta-vault/backlog|backlog]] соответствуют
реальности («запись без обновления карты = работа потеряна»). «Нечего
закрывать» — легальный ответ, но явный, одной строкой. Ритуал и опциональный
хук — `meta-vault/harness/automations/session-close.md`.

> Канон структуры: `meta-vault/vault-template.md` (база-баз). Правила письма:
> `meta-vault/principles.md`.
