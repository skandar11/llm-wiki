# Принципы (конвенции vault — база-баз)

Это **база** конвенций для всего неймспейса. Доменные vault (`project-vault`,
`office-vault`, …) фиксируют только свои **дельты** относительно этого файла.
Структура и точки входа — в [[meta-vault/vault-template|vault-template]]; этот
файл держит правила письма на уровне объектов.

**Ядро конвенций (база):**
один файл = один объект · имена = поисковые крючки · связи через `[[скобки]]` ·
плоская структура · обязательный frontmatter · без секретов в файлах (только
указатели) · один язык базы (см. ниже). Термины — канон в
[[meta-vault/glossary|glossary]] (level / stream / flow / meta-layer / zone /
engine).

## Уточнения и дельты верхнего уровня

- **Язык.** Выбери свой язык базы и держись его — критерий: на чём тебе
  естественно читать и искать. Пример раскладки: инфраструктурные файлы
  (двери, принципы, схемы) — на английском ради экономии токенов, живые
  тексты — на родном; или вся база целиком на одном языке. Дословные цитаты
  остаются на языке оригинала внутри файла; обёртка вокруг них — на языке базы.
  Уже написанные файлы ради одного языка не переписываются.
- **Sensitivity.** Frontmatter может нести `sensitivity: normal | private`.
  `private`-объекты и личные корпуса **никогда** не пушатся в публичный remote.
- **Hot-state верхнего уровня — backlog + inbox, не status.** На верху нет
  `status.md` и changelog **намеренно**: горячее состояние уровня = реестр
  [[meta-vault/backlog|backlog]] + дверь захвата inbox/. `status.md` живёт в
  доменных vault, где есть «состояние дела на сегодня».
- **Первоисточник не копируется.** Личный первоисточник (дневник, авторские
  тексты — если заведёшь такой домен) в этот vault не переносится. Он живёт
  по своему пути; здесь — только заметки *о* нём.
- **Поле `scope` (формализовано).** Любой объект может объявить `scope:
  personal | work | all` — кто его читает/использует. `all` = кросс-доменный
  канон (метод, глоссарий); `personal` = личные корпуса/заметки; `work` =
  проектное. Используется как фильтр метаданных.
- **Теги `axis` / `layer` (там, где снимают неоднозначность).** Доки об
  архитектуре / методе / решениях могут объявлять, на каком словаре стоят
  (канон: [[meta-vault/glossary|glossary]]): `axis: vault | agentic | engine |
  cross`. Для `axis: agentic` добавляется `layer: base | meta | hybrid` —
  *base* = производство продукта, *meta* = мета-слой (улучшение конвейера),
  *hybrid* = оба. Ставить только там, где проясняет; **не** навешивать на
  чистое содержимое (tech-профили, корпуса) или файлы, очевидные по папке.
- **Потолок размера — для справочных объектов, не для разборов.** Мягкий
  потолок ~120 строк относится к **односмысловым справочным** файлам.
  `decisions/` и доки `type: model` легитимно длиннее (они
  несут рассуждение, не одну справку) — их держит честными сильная внутренняя
  структура (заголовки, таблицы), а не счётчик строк.

## Frontmatter

Минимум для индексируемых файлов vault (расширяй по надобности; enum'ы ниже —
действующий контракт):

```yaml
---
type: corpus | person | note | ...
status: idea | proposed | accepted | active | superseded | archived
sensitivity: normal | private
scope: personal | work | all
tags: [hook1, hook2]
---
```
