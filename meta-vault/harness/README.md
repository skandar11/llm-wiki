# Harness — зона слоя

Знание harness-слоя: реестры, спеки, принципы. Термин «harness» —
[[../glossary|glossary]]: runtime-клиент, исполняющий агентов (Claude Code /
Codex / любой следующий); сменный и выкидываемый — данные должны его пережить.

## Карта

- [[automations]] — реестр автоматизаций (hooks / cron): таблица + правило
  добавления. Спека каждой автоматизации — свой файл `automations/<name>.md`.
  Первая: [[automations/session-close|session-close]].
- [[channels]] — каналы личной переписки (Telegram / WhatsApp): шаблон
  подключения, модель доступа, правила записи.

## Принципы слоя

- **Три рода вещей:** знание слоя (markdown) — здесь; исполнители (скрипты,
  гейты) — в своей папке кода внутри неймспейса, в git; конфиги — выкидываемый
  кэш харнесса (`~/.claude/` и т.п.), пересоздаются из спек.
- **Реестр = закон:** конфиг в кэше без строки в [[automations]] — баг.
  Автоматизация не существует, пока её нет в реестре: мета-оптимизация не
  должна обгонять контроль владельца.
- **Ревьюируемость:** слой автоматизаций всегда читаем владельцем; каждая
  ступень усиления (напоминание → гейт → авто-действие) — его явное слово.
- **Enforcement — код, не промпт:** правило, которое держится только текстом
  в инструкции агента, не держится. Настоящий гейт — в скрипте/хуке;
  текст в спеке — оборона в глубину.

## Связанность с харнессом

Знание зоны (спеки, реестры) — harness-независимый markdown. Реализации
(хуки, скрипты) связаны с конкретным харнессом — при смене инструмента они
пересобираются **из спек этой зоны**; слой данных не меняется.
